What is a Join?

A join combines rows from two or more tables based on a related column. Think of it like connecting spreadsheets that share a common piece of information — like an ID or a name.

users

1Alice

The orders.user_id column connects to users.id. Note: Bob (id=2) has no orders.

Without joins, you'd have to manually match records. With joins, the database does the matching for you — and different join types give you different results.

Join Types

INNER JOIN

Returns only rows that have matches in both tables. If a row doesn't have a matching partner, it's excluded.

Left table only Right table only Both tables
SELECT * FROM users INNER JOIN orders ON users.id = orders.user_id;

Result

idnameuser_idproduct
1Alice1Book
1Alice1Pen
3Carol3Notebook

3 rows returned. Bob (no orders) is excluded.

Use when: You only want rows that exist in both tables. Example: "Show users who have placed orders."

LEFT JOIN

Returns all rows from the left table, plus matching rows from the right table. If there's no match, the right side shows NULL.

All left Both tables
SELECT * FROM users LEFT JOIN orders ON users.id = orders.user_id;

Result

idnameuser_idproduct
1Alice1Book
1Alice1Pen
2BobNULLNULL
3Carol3Notebook

4 rows returned. Bob included with NULLs for missing data.

Use when: You want all items from one table, even if they have no related data. Example: "Show all users, even those who never ordered."

RIGHT JOIN

The opposite of LEFT JOIN. Returns all rows from the right table, plus matching rows from the left. If there's no match, the left side shows NULL.

Both tables All right
SELECT * FROM users RIGHT JOIN orders ON users.id = orders.user_id;

Result

idnameuser_idproduct
1Alice1Book
1Alice1Pen
3Carol3Notebook

3 rows returned. Same as INNER in this case (all orders have users).

Use when: You want all items from the right table, even if they have no match. Example: "Show all orders, even unassigned ones."

Try it in the visualizer

FULL OUTER JOIN

Returns everything from both tables. If rows don't have matches, NULLs fill the gaps on both sides.

Left only Both tables Right only
SELECT * FROM users FULL OUTER JOIN orders ON users.id = orders.user_id;

Result

idnameuser_idproduct
1Alice1Book
1Alice1Pen
2BobNULLNULL
3Carol3Notebook

4 rows returned. All users and all orders included.

Use when: You need a complete picture of both tables. Example: "Show all users and all orders, even unpaired ones."

Try it in the visualizer

CROSS JOIN

Returns the Cartesian product — every row from the left table paired with every row from the right table. No ON condition needed.

SELECT * FROM table_a CROSS JOIN table_b;

Result (using our example)

idnameuser_idproduct
1Alice1Book
1Alice1Pen
1Alice3Notebook
2Bob1Book
2Bob1Pen
2Bob3Notebook
3Carol1Book
3Carol1Pen
3Carol3Notebook

9 rows returned (3 users × 3 orders).

Warning: Results grow quickly. 10 rows × 10 rows = 100 rows. Use with caution on large tables.

Use when: Generating combinations (e.g., all shifts × all employees). Rarely used in production queries.

ANTI & SEMI Joins

These aren't standard SQL joins but are useful in Spark SQL and some databases.

LEFT SEMI JOIN

Returns rows from the left table that have at least one match in the right table. Like IN or EXISTS.

-- Equivalent to: WHERE column IN (SELECT ...)
Result (from users + orders)
idname
1Alice
3Carol

Bob excluded (no orders).

LEFT ANTI JOIN

Returns rows from the left table that have no match in the right table. Like NOT IN or NOT EXISTS.

-- Equivalent to: WHERE column NOT IN (SELECT ...)
Result (from users + orders)
idname
2Bob

Only Bob (no orders).

Note: These use Spark SQL syntax (LEFT SEMI JOIN, LEFT ANTI JOIN). In PostgreSQL or MySQL, use EXISTS or NOT EXISTS subqueries instead.

Quick Reference

Join Type Returns When to Use
INNER Matching rows only When you need data from both tables
LEFT All left + matches When the left table is primary
RIGHT All right + matches When the right table is primary
FULL OUTER All rows When you need the complete picture
CROSS Cartesian product Generating combinations (use sparingly)
SELF Rows matched to self Hierarchies, comparisons within a table
Set Operator Returns When to Use
UNION All rows (no duplicates) Combining similar data
INTERSECT Common rows only Finding overlaps
